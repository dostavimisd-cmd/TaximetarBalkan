## C) Patch-evi (ključne ideje)

### C1. task_handler.dart (K1, K3, K5, K6, V10, N3, N4, N6)
- `Future<void> _queue = Future.value();` — `onReceiveData` sinhron, komande lancem `_queue.then(_dispatch).catchError(...)` (start/stop/status redom).
- `_startTracking()` otvara `Geolocator.getPositionStream` + `Timer.periodic(10s, _saveSnapshot)` (`??=`), `_stopTracking()` ih gasi. Zove se iz `_handleStartCommand` posle inserta i iz oporavka; `onStart` samo oporavlja i šalje `ready{active}`.
- Svi `error` iz start/stop nose `cmd`.
- Stop: ako nema vožnje → `stopped{ride_id:null}`; inače cancel snapshot timer, izračunati FareResult, **transakcija** (update rides + delete snapshots); na grešku → `_startTracking()` + `error{cmd:'stop'}` i return (tracker ostaje); na uspeh → `_stopTracking()`, `stopped{ride_id, distance_m, waiting_sec, start_price, km_price, waiting_price, min_price_adjustment, total_price}`. `stopService()` NE zove handler, kontroler to radi.
- K1: `_tariffFromRide(ride)` i `_markInterrupted(ride, snap)`: računa FareCalculator iz snapshot-a, update rides (status interrupted, end_time=snap.timestamp, distance_m, waiting_time_sec, km_price, waiting_price, total_price, min_price_adjustment) + delete snapshots u transakciji; bez snapshot-a `end_time = start_time`. Koristi se u `_cleanupOldActiveRides` i zastareloj grani `_recoverActiveRide`.
- `_recoverActiveRide` vraća `bool`; bez snapshot-a a vožnja mlađa od 5 min → nastavi od nule (N6).
- Opcija "Nastavi / Završi" (status `suspended`, događaj `recoverable`) — tek posle testa na uređaju.

### C2. ride_service_controller.dart (K2, K5, V8, V9, U1)
- `_serialized(op)` — operacije connect/startRide se ne preklapaju.
- `connect()`: ako servis radi → `status` (Completer<Map>) ; ako ne → `_startServiceAndWait()`, pa ako `ready.active != true` odmah `_stopService()`.
- `startRide()` async: ako `_rideActive` → `already_active`; `_ensurePermissions`; ako `!_serviceReady` → `_startServiceAndWait()` (ako `ready.active` → false); pa `sendDataToTask start`.
- `stopped` → `_rideActive=false; _stopService()` (`_serviceReady=false; FlutterForegroundTask.stopService()`).
- `_ensurePermissions`: posle provere GPS-a `Geolocator.getLocationAccuracy() == LocationAccuracyStatus.reduced` → error `permanent: true`.
- `_initServiceOptions`: `allowAutoRestart: false`.

### C3. database_helper.dart v3 (U4, U8, N5, N7, N21)
```dart
version: 3,
onConfigure: (db) async {
  await db.rawQuery('PRAGMA journal_mode=WAL');
  await db.rawQuery('PRAGMA busy_timeout=5000');
  await db.execute('PRAGMA foreign_keys=ON');

// _upgradeDB: u oldVersion < 2 na početku: update rides set status='interrupted' where status='active'
// oldVersion < 3: ALTER ride_snapshots ADD saved_at INTEGER; ALTER rides ADD client_uuid TEXT;

```
Iste kolone/indeksi i u `_createDB`. `_saveSnapshot` upisuje `saved_at`; starost = `saved_at ?? timestamp`.

### C4. taximeter_provider.dart (K2, K3, K4, K6, V7, V8)
- `enum RidePhase { idle, starting, running, stopping, finished }`, `RideResult` (+`fromEvent`), `TaximeterState.phase`, `lastResult`, getteri `isRunning`/`isBusy`.
- `copyWith`: `errorMessage: clearError ? null : (errorMessage ?? this.errorMessage)`, isto za warning i `lastResult` (`clearResult`).
- `ready`/`status`/`started`/`recovered`/`stopped` koriste `clearError: true` umesto `errorMessage: null`.
- `recovered` preuzima distance/waitingMs/price (V7) + upozorenje "Vožnja je nastavljena posle prekida servisa."
- `stopped` → `finished` + `lastResult` + prikaz konačne cene; `ride_id == null` → `idle`.
- `error{cmd:start}` u `starting` → `idle`; `error{cmd:stop}` u `stopping` → `running`.
- `startRide` async, `stopRide` postavlja `stopping`, `newRide()`, `retryConnect()` + `AppLifecycleListener(onResume: retryConnect)`.

### C5. taximeter_screen.dart (samo diff, UI radi Gemini/korisnik)
Dugme "NOVA VOŽNJA" u fazi `finished`; Start onemogućen kad `isBusy`, a kad `!isReady` poziva `retryConnect`; Stop onemogućen u `isBusy`; prikaz `warningMessage` (amber) i stavki `lastResult`.
